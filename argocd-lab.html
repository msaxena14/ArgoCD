argocd-lab · app-of-apps pattern

One Seed, a Whole Fleet

A single bootstrap Application is applied by hand — once. Everything downstream cascades from git: an AppProject as the fence, an ApplicationSet stamping one Application per list entry, and multi-source Helm keeping charts generic while values/local/ carries the environment.

1 manual apply · everything else self-driving · prune + selfHeal at every level

VIEW 01 Repo layout — one manual file, three self-managed layers

Only bootstrap/ ever meets a human's kubectl. The argocd/ folder is self-managed the moment the seed exists; charts stay generic; environment specifics live apart in values/local/ so a future values/prod/ reuses the same charts untouched.

📁 argocd-lab/ ├── bootstrap/ │ └── bootstrap-app.yaml # kind: Application — the seedCRDMANUAL · ×1 ├── argocd/ # watched by the seed → self-managed foreverSELF-MANAGED │ ├── project.yaml # kind: AppProject "lab" — the fenceCRD │ └── applicationset.yaml # kind: ApplicationSet "lab-apps" — the stampCRD ├── charts/ # generic, reusable — no env knowledge │ ├── hello-world/ # minimal demo chart │ └── podinfo/ # upstream microservice: Redis subchart, gRPC, ServiceMonitor, PDB └── values/local/ # per-environment overlays, reached via $valuesENV: local ├── hello-world/values.yaml # replicaCount: 2 └── podinfo/values.yaml # replicas + UI message override

Adding a new app = 3 touches

1. Chart under charts/<name>/ · 2. Overrides under values/local/<name>/values.yaml · 3. One list entry:

- list: elements: - chartName: hello-world path: charts/hello-world + - chartName: <name> + path: charts/<name>

Argo CD picks up the entry and creates labs-<name> automatically — no kubectl beyond the original bootstrap. A new environment works the same way sideways: add values/prod/<name>/values.yaml and new generator entries (or a matrix generator); the charts never change.

The two rules this repo encodes: nothing runs from your laptop (Argo CD polls git and makes the cluster match), and every level sets automated: {prune: true, selfHeal: true} — so a kubectl edit on the cluster is reverted, and deleting a list entry deletes that whole app, with resources-finalizer.argocd.argoproj.io guaranteeing the cleanup actually happens instead of orphaning resources.
